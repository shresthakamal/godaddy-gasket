# Upgrade to v3

This guide will take you through updating `@gasket/*` packages from `2.x` to
`3.x`.

## Steps

## Fix `@gasket/cli` version

In older versions of the `@gasket/cli`, it installed itself in newly created
apps using `"latest"` as the version. It is a better practice to set this as a
compatible range. To fix this:

```bash
npm i @gasket/cli@^3.0.0
```

For new apps, the latest cli is now smart enough to install a version compatible
with the global version used to create the app.

To globally install the latest for creating new apps:

```bash
npm i -g @gasket/cli@^3.0.0
```

## Switch to `@gasket/godaddy-preset`

If your app is currently using the `@gasket/default-preset`, this is being
deprecated in favor of `@gasket/godaddy-preset`. Also, the "godaddy" preset uses
the new preset structure required by v3 of the CLI.

```bash
npm remove @gasket/default-preset
npm i @gasket/godaddy-preset
```

If you are migrating from a default version prior to 4.x, be sure to also add
`@gasket/cookies` as a direct dependency of your app.

```bash
npm i @gasket/cookies
```

#### Background

`@gasket/cookies` was removed as a direct dependency of `@gasket/intl` which
means your app need to install it to meet peerDependencies for other packages.

## Update `@gasket/godaddy-preset`

If your installation of `@gasket/godaddy-preset` did not change in the
[upgrade to latest steps], it's a good idea to re-install this module to update
the plugin dependencies.

```bash
npm i @gasket/godaddy-preset
```

## Upgrade `next@9`

When migrating to `@gasket/godaddy-preset` be sure to also upgrade your next
version to v9.

```bash
npm i next@^9.1.1 @gasket/next@^4.0.0
```

#### Background

There was a change to how Document and App need to be packaged when importing
from a shared node module. Be sure to upgrade these together.

## Upgrade `redux` and `react-redux`

## Fixup for `@gasket/next@3`

If you upgraded from a version prior to 3.0.0, you will need to a adjust how the
`./pages/_document.js` imports `Document`:

```diff
- import { Document } from '@gasket/next';
+ import Document from '@gasket/next/document';
```

#### Background

Before v3, `Document` was unnecessarily being included into webpack bundles.
This file is only needed by the server for rendering.


## Fixup for `@gasket/redux@3`

If you upgraded from a version prior to 3.0.0, you will need to do two things.

### Register @gasket reducers

There are two scenarios to consider:

**A) You do not already have a `./store.js` file.**

In this case, it's easiest to copy over this file to the root of your app:

- [@gasket/uxp-plugin/generator/store.js]

**B) You do have a `./store.js`.**

In this case, you need to add reducers from auth, intl, and cookies.

```diff
const { configureMakeStore } = require('@gasket/redux');
const myAppReducers = require('./redux/reducers');
+ const authReducers = require('@gasket/auth/reducers');
+ const intlReducers = require('@gasket/intl/reducers');
+ const cookiesReducers = require('@gasket/cookies/reducers');

const reducers = {
  ...myAppReducers,
+  ...authReducers,
+  ...intlReducers,
+  ...cookiesReducers
};

module.exports = configureMakeStore({ reducers });
```

#### Background

The default `@gasket/redux/make-store` no longer includes previously _built-in_
reducers which were GoDaddy specific and are not going to be open-sourced.
Instead, you will need to add these to the `./store.js` at the root of your app.

For new apps, this is generated by the `@gasket/uxp-plugin`. However, existing
apps will need to create this file

For additional reference, see the [upgrade PR] in the canary-app.

### Replace dynamic reducers

In the latest version of `@gasket/redux`, the `withReducers` React HOC is no
longer available. Instead, register all your reducers in the `./store.js` file.

```diff
// example-component.js
import React from 'react';
import { connect } from 'react-redux';
- import { withReducers } from '@gasket/redux';
- const myAppReducers = require('./redux/reducers');

// -- snip --

- export default withReducers(myAppReducers)(
-  connect(mapStateToProps)(ExampleComponent));
+ export default connect(mapStateToProps)(ExampleComponent);
```

```diff
// store.js
const { configureMakeStore } = require('@gasket/redux');
const authReducers = require('@gasket/auth/reducers');
const intlReducers = require('@gasket/intl/reducers');
const cookiesReducers = require('@gasket/cookies/reducers');
+ const myAppReducers = require('./redux/reducers');

const reducers = {
  ...authReducers,
  ...intlReducers,
  ...cookiesReducers,
+  ...myAppReducers
};

module.exports = configureMakeStore({ reducers });
```

#### Background

This was removed for a number of reason to support our open source efforts:

1. It was react-specific, which made this package messy for non-react uses.
2. It doesn't work with react-redux v6 or v7 currently due to
   [an open issue](https://github.com/ioof-holdings/redux-dynostore/issues/20)
   in a dependency package. By dropping, it's one less thing to worry about and
   bundle.
3. With the open-source changes, GoDaddy gasket apps will need to define the
   store.js file anyway, as mentioned above, so this will always be in place to
   register new reducers for an app.
4. It doesn't provide a whole lot of value to end-users. Yes, it allows for code
   splitting, but reducers generally are used on more than a few pages which
   means they end up in the common chunk anyway and aren't all that big.

If your app was using `withReducers` before, you can simply move them to be
registered in the `./store.js`. One gotcha, however, is if your reducers and
related code was written with ES6 imports, you'll need to modify them to use
CommonJS since the `./store.js` is also loaded by the server. Read more on this
in the [gotchas].


## Upgrade devDependencies

At this point, it is a good idea to make a commit of your upgrades, if you have
not been already. Now, make sure tests and lints pass in the app's current form.
This way it is easier to rule out broken tests from package upgrades, or from
test dependency upgrades. Since upgrading your testing dependencies is less
critical, these can be upgraded more slowly, such as a separate tech dept
test/task, especially if test fixup is required.
